# Workspace 上下文与用户提问

受治理的 Workspace 在执行前准备上下文；查找、工具故障和预算触发由 Host 判断，不依赖模型遵守提示。`ask_user` 继续作为同事主动提问的工具。普通 CLI 的其它执行入口不因此获得 Workspace 权限。

## 开工前

Host 在写入已接受请求、派发模型之前，核对当前资源绑定并构造只读上下文：

- 个人本地模式仅使用 Host 绑定的个人 home 中已有 `~/.hara/memory/MEMORY.md`、`USER.md`，每个来源最多 256 KiB。拒绝链接、其它所有者、可由其它用户改写的路径和完全公开的路径链。经核验的私有容器内兼容旧 Markdown 文件权限；不自动 chmod 或迁移。不可读时标记不可用，不扩大搜索范围。帐号型 Workspace 不继承个人来源。
- 当前 Workspace 已授权的两处记忆目录，每处仅上述两个文件；派生词法索引最多每层 1000 条、每段 384 UTF-8 字节。
- 当前同事 ID、当前名、用户名、配置历史中的旧名与明确合并链。最多索引 512 位同事、每位 64 个别名。合并只接受同范围已归档源及可访问的活动目标，不猜测相似名字、不迁移会话或凭据。现阶段只提供 Host 服务层登记，不开放模型/HTTP 合并入口。

注入模型的上下文包上限 4096 UTF-8 字节，名册与记忆分别限制为 2200/1400 字节，相关条目优先且两层记忆交替保留；查询工具 `workspace_context_lookup` 只接受最长 200 字符的 `query`，返回最多 8 个候选和 8 条短记忆。正文先做完整来源的秘密/注入扫描，再分段与截断；所有记忆和名册仍是不可信历史数据，不代表工具授权或完成证据。截断/不可见明确标记，不伪称检索完整。

已有名册证据产生歧义时可在首个模型请求之前提问。明确的未知同事问句也会先停；该规则仅覆盖实现中的中英文句式，不宣称能确定任意自然语言的含义。正常问候、已明确的文件任务不会仅因无记忆而暂停。复杂歧义仍可由同事调用 `ask_user`，后续结构化查找受同一硬闸约束。

## 硬触发与派发

| 条件 | Host 行为 |
| --- | --- |
| 上下文准备未完成，或索引结构/范围校验失败 | 不接受执行，不调用模型；返回明确失败。缺少可选记忆与损坏索引分开处理。 |
| 一次结构化检索返回多个实际身份 | 立即保存一个问题；选项仅来自有证据且可区分的身份标签。 |
| 两次未解决查找 | 进入等待。上下文/记忆空结果以及 `workspace_read` 的不存在结果累计；改查询、穿插成功结果或重启不清零。用户有效回答才开启下一个有界查找窗口。 |
| 连续两次真实工具失败 | 保存工具卡点问题；一次成功工具可清除连续故障计数，但不清空未解决查找数。 |
| 委派树实际轮数、工具数或总传输 token 达冻结上限 80%，或本次 attempt 时间达 80% | 在下一次派发前提问。相同预算预警仅确认一次；确认不增加上限。已耗尽时仍禁止继续。时限保持原有每 attempt 语义，等待用户不占活动 attempt。 |
| 同事显式 `ask_user` | 同样保存问题和检查点，不默认回答、不超时批准。 |

工具派发串行经过同一 Host 检查。包含上下文/记忆/名册查询的批次不会混跑业务动作；第三个排队查找、同批后续写入和下一轮模型都不能越过已生效的问题。不能把成功身份命中因没有记忆片段误算为查找失败。

状态在原 Workspace 的 `interaction-<runId>.json` 中通过私有文件、CAS 和身份围栏保存，包含问题、准备标记、查找/故障数、预算确认及有限回答去重 ID。模型参数不能修改它。任务的 `material_choice`/`awaiting_user` 检查点和真实已闭合历史是继续依据；UI 的等待投影不代表任务已完成。

## 回答与保留暂停

服务端通过 `workspace.user-interaction.v1` 协商新协议。所有操作继续要求现有本机连接身份、选中 Workspace、当前 generation、同事及会话租约。

| RPC | 字段（除现有传输信封外） |
| --- | --- |
| `workspace.session.answer` | `workspaceId`, `expectedGeneration`, `agentId`, `questionId`, `message`, `requestId` |
| `workspace.channels.answer` | 同上，另加 `channelId`；只恢复该频道内被回答的同事 |
| `workspace.session.pause-question` | `workspaceId`, `expectedGeneration`, `agentId`, `questionId` |
| `workspace.channels.pause-question` | 同上，另加 `channelId` |

回答不接受空值或 `/continue` 代替选择。普通 send/resume 不能绕开当前问题。同一 requestId 同内容返回原回执，异内容拒绝；两个连接竞争同一问题至多接受一个。结果不明只读核对原回执，不自动重发。回答先写入原 Task decision，再继续原 taskId/runId；新 turn/attempt 保持原权限、冻结配置和累计轮数/工具/token。崩溃恢复核对已保存回答，重复核对不能清除后来的失败计数。

“先停在这里”是无模型调用的显式状态操作：保留问题、检查点和旧预算，可另开明确的新任务；继续旧任务时原问题重新出现，不把暂停当成回答。达到硬额度的任务也能保留暂停，不要求通过一个永远不可用的继续按钮。

Desktop 在私聊和本地频道呈现问题、保存的卡点、已有候选及自由回答。预算/连接不满足时禁止回答派发，连接修复仍可用；排空期间不会假装工具已停。切换 Workspace/同事/频道后，迟到的答案和暂停回执不能影响另一个视图。没有新能力的旧运行时不降级成普通新任务。

## 验证与整合边界

回归使用临时 HOME、合成记忆和合成 provider：开工顺序、实际双层命中、改名/合并、秘密与链接拒绝、两次失败及串行第三次拦截、80% 边界、重启/并发/幂等、原步骤继续且已写文件不重写、预算耗尽与明确保留暂停、频道隔离及三语言 UI。

本功能不实现记忆 v2 存储、向量索引、管理界面、备份/卸载和删除联动；见 [记忆设计](MEMORY-DESIGN.md)。Desktop 功能候选必须与包含此能力的 Core 配对验证，正式发布前重新固定经批准的 sidecar SHA。源码测试和旧 sidecar 锁的 CI 不能证明正式候选包已包含新协议。本变更不执行发布、签名或用户数据迁移。
