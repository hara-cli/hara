# Agent Hub passive inbox foundation

This slice provides a Host-owned passive inbox, a separate authenticated loopback listener, and the G0 adapter ports. It does not enable Agent Hub in the production Workspace Host, expose a model/MCP tool, implement `hara send`, send to an external agent, or run a colleague. Those entry points remain separate slices. No dependency or native cache was added.

## Shared C0 and G0 boundaries

`src/agent-hub/contracts.ts` deliberately defines no competing actor kind, human principal, command receipt, or execution status. `AgentHubBoundaryContract<ExternalSource, SavedReceipt>` requires C0-owned factories and validators. The directory is a synchronous exact lookup of already-registered local metadata. It must not discover native sessions, read their messages, or capture tmux panes. G0 egress is a type-only port for a later adapter, not a claim that current `ag send` supplies privacy-preserving discovery or precise receipts.

An external message is never a human command. C0 command acceptance, execution, drain and task completion must not be inferred from a mailbox save or transport ACK. The production-shaped adapter in `src/agent-hub/c0-adapter.ts` imports the canonical C0 v1 types, parser, factories and error/retry table. It creates only `external-agent-source` with a null human principal and `hub-ingress-receipt`/`saved`; transport types are shared but real egress remains a later slice. Synthetic port fixtures remain for storage fault injection, with additional real-C0 storage/HTTP regression coverage. No C0 source is copied or redefined.

## Host ownership and credentials

Construct `AgentHubStore` with the explicit private home and the C0 `scopeKey`/`generation` obtained by the trusted Host. Neither comes from the network request. The required `assertCurrent` callback belongs to the live C1 Host authority; it runs on each operation and before admission/commit. Parsing a C0 context or accepting a client capability is not an authority check. Each scope has its own private namespace. A new generation invalidates old grants while preserving old messages for display. The registered instance and alias are checked before reading the body and again during commit. Unknown/stale registration fails closed. Historical records are validated with the canonical C0 parser in their exact scope, so a new generation can still display history. New admissions use the current C0 factories, current Host authority and current-generation grants; historical parsing does not revive old credentials or approvals.

Only the trusted Host API can issue, rotate or revoke grants. A grant contains 256 random bits. The catalog keeps only its SHA256, not the raw token. `writeAgentHubCredential` provides an exclusive 0600 handoff below a prevalidated 0700 directory chosen by the trusted native flow. It rejects preseeded files/links and remote endpoints. The returned raw grant is only for that native connection/handoff flow; it must never enter a conversation, general Workspace discovery receipt, URL, log or command argument. No network mint/rotate/revoke endpoint exists. Token possession is a local capability, not proof of a human action or protection from an unrestricted malicious process running as the same OS user.

The default and maximum per-inbox ceiling is 128 MiB. The required `HaraStorageQuota` is a separate home-wide persisted policy and mutex: every Hub scope shares it. Its total byte limit is explicitly provided by the trusted Host, rather than guessed from an Agent request. It counts the default private `.hara` tree and the Host's additional prevalidated Hara-owned storage roots using metadata only. The registered root set and limit are persisted; a second scope/process cannot omit a root or silently increase the limit. Symbolic links, including dangling and directory links, contribute their own lstat size and are never resolved or traversed. Unknown special files/census failures refuse new data rather than reporting zero. Unrelated project/sender files are not storage roots.

Hub scopes retain their own state locks. A short global critical section persists a peak-byte reservation; payload reads/writes, fsync/publication fences, Host callbacks and whole-home census happen outside that global lock. Trusted file mutation wrappers settle exact size deltas, including partial publication/error paths, before releasing the reservation. Other scopes/processes include all outstanding reservations in admission; a changed policy is checked again before publication. Frozen private directory bindings avoid repeating path setup while every IO/publication still checks canonical path, dev/ino, private mode and regular-file identity. Other Hara domains are included in usage; their future writers must also use this common controller for coordinated admission. This change does not rewrite unrelated legacy writers or claim an OS filesystem hard quota. Fixed-schema revocation, cleanup recovery and at most eight durable read leases retain bounded control writes (at most 64 KiB per small control write; a CAS-bound restrictive catalog replacement is additionally allowed up to 4 MiB only when its permanent byte size does not grow) at a full data budget. These control bytes, staging copies and orphaned files still count against subsequent new-data admissions; they are not unmetered payload capacity. No receive path silently deletes content.

## Accounting cache, startup and policy changes

`await store.prepare()` (also called before the library listener starts) performs cold reconciliation before any HTTP deadline or listener exists. Cold census is metadata-only, outside the global lock. A schema-1 quota policy upgrades to the versioned accounting record without widening its root set/limit or deleting data. A fresh persisted record makes another process/restart cheap.

Every Hub mutation is incrementally charged. Legacy Hara writers are cached: the Host must call `await globalQuota.refreshUsage()` after known unmanaged mutations. On activity, an estimate older than 30 seconds requests an asynchronous, metadata-only reconciliation; retries are limited to one per 30 seconds. The scan never holds the global lock. A changed ledger revision or active/unknown writer discards the candidate instead of overwriting admitted deltas. Unknown/crashed mutation reservations remain conservatively charged until a successful fenced census; startup also checks for retired reservations. The synchronous mutation guard still refuses new data from a snapshot older than five minutes; bounded revocation/recovery writes remain available. This is bounded-staleness cooperative accounting, not instantaneous monitoring of unrelated legacy writers or an OS filesystem quota. Cold startup and background calibration are reported separately from hot-message latency.

Before HTTP message writes, `await store.prepareReceive(token, { timeoutMs, signal })` authenticates using a verified atomic catalog snapshot, then awaits `globalQuota.prepareWrite` only if the accounting snapshot is expired or has an uncertain/retired reservation. Credential reads do not schedule census work, so an unauthorized request cannot trigger a whole-home scan. Fresh snapshots retain the fast path. Reconciliation shares the controller's single-flight promise with background/other ingress waiters and never holds a quota or scope lock while awaiting. Each caller has at most seven seconds, within the remaining ten-second HTTP request budget (including body intake and preliminary authentication), and at most two reconciliation attempts. Every completion re-reads freshness, even when a competing census invalidated its CAS. Persistent contention, IO failure or a deadline returns the canonical `store_unavailable` response. A canceled/expired waiter may leave a shared accounting-only census running for another caller; it cannot later publish its message. No resident timer is added.

After waiting, the Store rechecks the current Host, generation, registration pair and credential revocation; ingress also rechecks its lifecycle/client/deadline before calling synchronous `receive` exactly once. Existing commit/publication fences remain in place. Neither preparation nor a caught `store_unavailable` automatically retries a receive operation. An unknown outcome is queried by its original request ID. Ordinary idle time no longer requires the sender to fail once and resend. Calibration latency is separate from hot-message latency.

`globalQuota.policy()` inspects the persisted policy revision/limit even when a restarted Host's configured limit has changed. Inspection and schema-1 accounting upgrade retain the old budget; they never widen it. The trusted Host can call `changeLimit({ expectedRevision, expectedLimitBytes, limitBytes }, authorize)`. The synchronous authorization must validate a native human/config action bound to that exact immutable request, before the short CAS lock; stale revisions fail. Existing bound controllers adopt the approved shared policy, and newly constructed controllers use its current configured limit. Shrinking preserves all content and pending reservations, blocks new growth when over budget, and still permits bounded revocation/recovery. There is no network or model route for migration and no implicit widening from another scope. `run` callbacks are synchronous; payloads are written only within their durable reservation.

## Narrow transport

`startAgentHubIngress` opens an ephemeral port on `127.0.0.1` only. It accepts an exact loopback Host, JSON POST, and `Authorization: Bearer <per-agent token>`. Browser Origin/Fetch-Metadata requests are refused. There is no CORS, general WebSocket initialization, file-path, session read/resume, task or schedule route. Header/body/concurrent-upload/connection/time limits are finite. The Host supplies the C0 error projection, which receives a fixed classification rather than arbitrary exception text.

The only paths are:

- `POST /v1/agent-hub/messages`: exact body `{ requestId, from, text, attachments }`.
- `POST /v1/agent-hub/receipts`: exact body `{ requestId }`; only the authenticated connection's receipt is returned, or null.

`from` must match the authenticated registration; it cannot select the true source. Any actor/human/approval/Workspace/permission fields are rejected. Incoming approval-looking text remains text. The saved receipt is persisted before returning. No callback for starting models, tools, tasks or schedules is accepted.

## Persistence and retry

Private directories/files use the existing Hara 0700/0600, no-follow, inode, hardlink, atomic-write and cross-process lock primitives. Binary publication now accepts the same synchronous authority fence, checked again after staging and before publishing. Catalogs and stored messages are parsed and bounded; damaged, missing-but-nonempty, aliased or foreign state fails closed instead of becoming an empty mailbox.

The stable request key is `(connectionId, requestId)`, including across token rotation. Equal retries return the original C0 receipt; changed content conflicts. Reinstating a different registered instance requires a new connection. A crash after immutable message publication and before catalog commit leaves one deterministic, quota-accounted orphan. Ordinary retry requires matching connection/request/digest and a source semantically equal to the current canonical factory output for the authenticated registered pair and Host binding. JSON property order does not matter. Same-scope historical parsing alone cannot authorize recovery: an old source generation or different external agent/instance returns conflict before publication and retains metadata, payloads, catalog and sequence unchanged. A matching current-source retry reuses original provenance, receivedAt and assets. No implicit relabeling or separately authorized historical recovery path is provided. Historical guards remain display readers, not current credentials, UserAction or C1 authority proofs. It is not silently replayed as a task. Unread is based on committed sequence numbers; marking read cannot consume future arrivals or move backward.

The quota counts raw payload files, catalog/message/control metadata, orphan/staging files and replacement peak space. Base64 exists only in the bounded ingress envelope; it is not retained in message metadata or payload files. Full storage rejects new content without eviction. Revocation remains available even when the configured content quota is full; disk/permission failure is still reported rather than claimed as a successful revoke.

## Attachments and preview quarantine

Text is at most 32 KiB UTF-8. A message has at most four files, each at most 8 MiB, totaling at most 16 MiB of decoded bytes. Exact canonical base64, safe display names, extension/type agreement and bounded image dimensions/container framing are checked. PNG/JPEG/WebP are limited to 20 MP and 8192 per dimension; animated PNG/WebP and other image formats are refused. MD/TXT are strict text; PDF is download-only. Executables, HTML, archives, video and unspecified types are refused.

Images are stored with `preview: "quarantined"`. Container/header checks are **not** a complete bitstream decoder. A future Desktop/media adapter must perform bounded trusted decoding and matching dimension/frame verification before any inline preview; this slice neither decodes via an external binary nor advertises preview capability. Malformed images can therefore remain quarantined rather than becoming executable/rendered content.

Content is copied into separate private immutable text and attachment files, never read again through the sender's original path. Storage schema 2 keeps each message's source, text preview/hash and attachment metadata in a file capped at 64 KiB. Listing only opens metadata, never a body/blob. A serialized page is capped at 256 KiB and 50 items; callers continue after the last returned sequence. Full text is fetched separately with its 32 KiB limit/hash check. A selected attachment streams in chunks no larger than 64 KiB and verifies its complete hash; consumers must await verified completion before saving/rendering it. Version-2 durable reader records protect a live stream for 30 seconds and renew on pulls when half that interval remains. There is no timer that keeps a crashed or abandoned reader alive. Before every chunk the same lease/inode must still exist and be unexpired; a stale reader fails with conflict and must explicitly reopen. Normal completion/abort removes only its exact current record. Cleanup planning, opening another reader, or the trusted `reapExpiredReadLeases()` API retires valid expired records, without deleting any payload or granting cleanup consent. Malformed/unknown records fail closed. Pre-enable version-1 records get a finite grace from verified inode mtime; the Host must drain the old Core before enabling this lease protocol. Process-tree drain remains the shared lifecycle layer's responsibility.

Pre-enable schema-1 inline records are rejected and retained, never implicitly reset or destructively migrated. An actual existing installation needs a separately verified migration before use. Raw token holders cannot enumerate inbox messages, fetch payloads or invoke cleanup; these remain trusted Host APIs, without a network route or runtime directory grant.

## Confirmed quota cleanup

`planAttachmentCleanup` produces a five-minute preview of the oldest eligible private attachment copies, with bounded candidates and exact metadata/inode snapshots. It includes unpublished attachment orphans, but preserves text bodies, message/source metadata, receipts and recovery records. The Host must explicitly confirm that each target has no forward/material/pinned/recovery references; unknown protection state is not eligible. Valid unexpired durable read leases are protected; expiration retires only the control record, and payload deletion still needs this independent plan/reference/native-confirmation flow.

`cleanupAttachments` requires a native human action bound to the plan digest, current scope/generation and current authority; `approved: true` or an Agent message is not a proof. The preview is revalidated before the first mutation, references are rechecked at publication/deletion, and a changed catalog or inode refuses the operation. Published attachments become `expired` tombstones before their exact private copy is removed. The sender's original file is never touched. Unpublished metadata/text remains recoverable; a later identical receive can restore the missing copy before its first ACK.

A private cleanup journal permits explicit recovery after interruption. Completed retries return the original receipt and cannot delete a newly restored orphan upload. Partial recovery requires current native confirmation again; no cleanup is resumed automatically. Receipts report validated payload bytes actually removed, separately from already-missing targets, rather than claiming exclusive physical disk space. Stored control/journal bytes remain part of global usage. Production UI must display the preview and obtain this native action before applying a plan.

## Verification and enablement gate

Focused tests exercise wrong source/extra authority fields, registration reuse, revocation during streaming, cross-scope/generation rejection, ACK loss/restart/token rotation, interrupted commit recovery, unread, quota/no eviction, links/corruption, attachment quarantine and the actual loopback listener. Tests use isolated synthetic state and zero model/provider calls.

Before enabling the feature, review the C0 v1 adapter together with its shared contract dependency; connect real registered-only G0 metadata; connect trusted native token handoff, the complete shared storage-root registry and native cleanup/reference/lifecycle authority; then wire CLI/Host/UI as separate reviewed slices. Transport submission does not prove an external agent read or executed anything. Human sends/forwards and future approval cards retain their independent authority checks.
